# Generated Code Examples

This document shows examples of code generated by protoc-gen-struct for different languages.

## Input Proto

```proto
syntax = "proto3";
package myapp;

message Person {
  string first_name = 1;
  string last_name = 2;
  int32 age = 3;
  bool active = 4;
}

message Book {
  string title = 1;
  int32 pages = 2;
  Person author = 3;
  repeated string tags = 4;
}
```

## Output Layout

One output file is produced per input proto, keeping the source directory:
`a/b/msg.proto` becomes `a/b/msg.go`. Two protos of the same name in different directories
therefore keep separate outputs.

Messages are emitted in dependency order rather than declaration order: a message is written
after every message it holds by value. This is what lets a C++ struct name another struct as a
member.

Nested messages are flattened into file scope under a qualified name, so `User.Inner` becomes
`User_Inner`. Two messages that each nest an `Inner` stay distinct.

## Generated Go Code

```go
// Code generated by github.com/David0922/protoc-gen-struct. DO NOT EDIT.

package myapp

import (
	"encoding/json"

	"go.yaml.in/yaml/v4"
)

// Person is a generated struct from proto message myapp.Person
type Person struct {
	FirstName string `json:"first_name" yaml:"first_name"`
	LastName string `json:"last_name" yaml:"last_name"`
	Age int32 `json:"age" yaml:"age"`
	Active bool `json:"active" yaml:"active"`
}

// ToJSON serializes Person to JSON.
// it converts the struct to a JSON byte slice.
// returns the JSON bytes and any marshaling error
func (x *Person) ToJSON() ([]byte, error) {
	return json.Marshal(x)
}

// FromJSON deserializes Person from JSON.
// it unmarshals the JSON byte slice into the struct, replacing any value it already held.
// returns an error if unmarshaling fails
func (x *Person) FromJSON(data []byte) error {
	*x = Person{}
	return json.Unmarshal(data, x)
}

// ToYAML serializes Person to YAML.
// it converts the struct to a YAML byte slice.
// returns the YAML bytes and any marshaling error
func (x *Person) ToYAML() ([]byte, error) {
	return yaml.Marshal(x)
}

// FromYAML deserializes Person from YAML.
// it unmarshals the YAML byte slice into the struct, replacing any value it already held.
// returns an error if unmarshaling fails
func (x *Person) FromYAML(data []byte) error {
	*x = Person{}
	return yaml.Unmarshal(data, x)
}

// ... (Book struct and methods follow same pattern)
```

## Generated C++ Code

A message-typed field is serialized through nlohmann's `to_json`/`from_json` overloads and
yaml-cpp's `YAML::convert` specialization, not through the member functions directly. Both are
looked up by name at the point of use, so the header declares them before the first struct that
needs one and defines them afterwards:

```cpp
// Code generated by github.com/David0922/protoc-gen-struct. DO NOT EDIT.

#ifndef PROTO_BOOK_156E6F88_H_
#define PROTO_BOOK_156E6F88_H_

#include <string>
#include <vector>
#include <map>
#include <optional>
#include <nlohmann/json.hpp>
#include <yaml-cpp/yaml.h>

namespace myapp {

struct Person;
struct Book;

inline void to_json(nlohmann::json& j, const Person& value);
inline void from_json(const nlohmann::json& j, Person& value);
inline void to_json(nlohmann::json& j, const Book& value);
inline void from_json(const nlohmann::json& j, Book& value);

} // namespace myapp

namespace YAML {

template <>
struct convert<::myapp::Person> {
  static Node encode(const ::myapp::Person& value);
  static bool decode(const Node& node, ::myapp::Person& value);
};

// ... (Book follows the same pattern)

} // namespace YAML

namespace myapp {

// Person is a generated struct from proto message myapp.Person
struct Person {
  std::string first_name;
  std::string last_name;
  int32_t age = 0;
  bool active = false;

  nlohmann::json ToJSON() const {
    nlohmann::json j;
    j["first_name"] = this->first_name;
    j["last_name"] = this->last_name;
    j["age"] = this->age;
    j["active"] = this->active;
    return j;
  }

  void FromJSON(const nlohmann::json& j) {
    if (j.contains("first_name")) {
      this->first_name = j["first_name"].get<std::string>();
    }
    // ... (other fields)
  }

  YAML::Node ToYAML() const {
    YAML::Node node;
    node["first_name"] = this->first_name;
    // ... (other fields)
    return node;
  }

  void FromYAML(const YAML::Node& node) {
    if (node["first_name"]) {
      this->first_name = node["first_name"].as<std::string>();
    }
    // ... (other fields)
  }

};

inline void to_json(nlohmann::json& j, const Person& value) {
  j = value.ToJSON();
}

inline void from_json(const nlohmann::json& j, Person& value) {
  value.FromJSON(j);
}

// Book is a generated struct from proto message myapp.Book
struct Book {
  std::string title;
  int32_t pages = 0;
  Person author;
  std::vector<std::string> tags;

  nlohmann::json ToJSON() const {
    nlohmann::json j;
    j["title"] = this->title;
    j["pages"] = this->pages;
    j["author"] = this->author;
    j["tags"] = this->tags;
    return j;
  }

  // ... (FromJSON, ToYAML, FromYAML follow similar pattern)
};

// ... (Book converters follow the same pattern)

} // namespace myapp

namespace YAML {

inline Node convert<::myapp::Person>::encode(const ::myapp::Person& value) {
  return value.ToYAML();
}

inline bool convert<::myapp::Person>::decode(const Node& node, ::myapp::Person& value) {
  if (!node.IsMap()) {
    return false;
  }
  value.FromYAML(node);
  return true;
}

// ... (Book follows the same pattern)

} // namespace YAML

#endif // PROTO_BOOK_156E6F88_H_
```

## Generated Python Code

`to_dict` and `from_dict` carry the nesting: `json.dumps` cannot encode a dataclass, and
`yaml.dump` would write a `!!python/object:` tag that `yaml.safe_load` refuses to read back, so
every message-typed field is converted to and from a plain dict.

Every field has a default, so a message can be built from JSON that leaves fields out — which is
what the other three generators produce for an unset `optional`.

```python
# Code generated by github.com/David0922/protoc-gen-struct. DO NOT EDIT.

from __future__ import annotations

from dataclasses import dataclass, field
import json
import yaml
from typing import Any, Dict, List

@dataclass
class Person:
    """generated from proto message myapp.Person."""

    first_name: str = ""
    last_name: str = ""
    age: int = 0
    active: bool = False

    def to_dict(self) -> Dict[str, Any]:
        """convert to a plain dict.
        nested messages are converted recursively, and an unset optional field is left out.
        returns the dict representation of this Person
        """
        data: Dict[str, Any] = {}
        data["first_name"] = self.first_name
        data["last_name"] = self.last_name
        data["age"] = self.age
        data["active"] = self.active
        return data

    @classmethod
    def from_dict(cls, data: Dict[str, Any] | None) -> 'Person':
        """build a Person from a plain dict.
        nested messages are rebuilt recursively, and a missing field takes its default.
        a data of None builds a Person with every field defaulted.
        returns a new Person instance
        """
        data = data or {}
        return cls(
            first_name=data.get("first_name") if data.get("first_name") is not None else "",
            last_name=data.get("last_name") if data.get("last_name") is not None else "",
            age=data.get("age") if data.get("age") is not None else 0,
            active=data.get("active") if data.get("active") is not None else False,
        )

    def to_json(self) -> str:
        """serialize to JSON string.
        returns the JSON string representation of this Person.
        raises TypeError if serialization fails
        """
        return json.dumps(self.to_dict())

    @classmethod
    def from_json(cls, data: str) -> 'Person':
        """deserialize from JSON string.
        takes a JSON string and returns a new Person instance.
        raises json.JSONDecodeError if the JSON is invalid
        """
        parsed: Dict[str, Any] | None = json.loads(data)
        return cls.from_dict(parsed)

    def to_yaml(self) -> str:
        """serialize to YAML string.
        returns the YAML string representation of this Person.
        raises yaml.YAMLError if serialization fails
        """
        result: str = yaml.safe_dump(self.to_dict())
        return result

    @classmethod
    def from_yaml(cls, data: str) -> 'Person':
        """deserialize from YAML string.
        takes a YAML string and returns a new Person instance.
        raises yaml.YAMLError if the YAML is invalid
        """
        parsed: Dict[str, Any] | None = yaml.safe_load(data)
        return cls.from_dict(parsed)

@dataclass
class Book:
    """generated from proto message myapp.Book."""

    title: str = ""
    pages: int = 0
    author: Person = field(default_factory=lambda: Person())
    tags: List[str] = field(default_factory=lambda: [])

    def to_dict(self) -> Dict[str, Any]:
        data: Dict[str, Any] = {}
        data["title"] = self.title
        data["pages"] = self.pages
        data["author"] = self.author.to_dict()
        data["tags"] = list(self.tags)
        return data

    @classmethod
    def from_dict(cls, data: Dict[str, Any] | None) -> 'Book':
        data = data or {}
        return cls(
            title=data.get("title") if data.get("title") is not None else "",
            pages=data.get("pages") if data.get("pages") is not None else 0,
            author=Person.from_dict(data.get("author")) if data.get("author") is not None else Person(),
            tags=list(data.get("tags") or []),
        )

    # ... (to_json, from_json, to_yaml, from_yaml follow same pattern)
```

## Generated TypeScript Code

Properties are named after the proto field, which is also the key the C++, Go and Python
generators serialize under. `fromJSON` does not translate keys, so camelCasing them here would
leave every field `undefined` when reading output any of the other three wrote.

Decoding goes through `fromObject`, which rebuilds the value property by property. Casting the
parsed document straight to the interface would assert every property is present without making
it so, leaving a missing array `undefined` and throwing on first use.

```typescript
// Code generated by github.com/David0922/protoc-gen-struct. DO NOT EDIT.

import * as yaml from "yaml";

// Person is a generated interface from proto message myapp.Person
export interface Person {
  first_name: string;
  last_name: string;
  age: number;
  active: boolean;
}

export namespace Person {
  export function toJSON(obj: Person): string {
    return JSON.stringify(obj);
  }

  export function fromJSON(data: string): Person {
    return fromObject(JSON.parse(data));
  }

  export function toYAML(obj: Person): string {
    return yaml.stringify(obj);
  }

  export function fromYAML(data: string): Person {
    return fromObject(yaml.parse(data));
  }

  export function fromObject(data: unknown): Person {
    const source = (data ?? {}) as Record<string, unknown>;
    const result: Person = {
      first_name: (source["first_name"] ?? "") as string,
      last_name: (source["last_name"] ?? "") as string,
      age: (source["age"] ?? 0) as number,
      active: (source["active"] ?? false) as boolean,
    };
    return result;
  }
}

// Book is a generated interface from proto message myapp.Book
export interface Book {
  title: string;
  pages: number;
  author: Person;
  tags: string[];
}

export namespace Book {
  export function fromObject(data: unknown): Book {
    const source = (data ?? {}) as Record<string, unknown>;
    const result: Book = {
      title: (source["title"] ?? "") as string,
      pages: (source["pages"] ?? 0) as number,
      author: Person.fromObject(source["author"]),
      tags: (source["tags"] ?? []) as string[],
    };
    return result;
  }

  // ... (toJSON, fromJSON, toYAML, fromYAML follow same pattern)
}
```

```typescript
// a document that leaves fields out still produces a usable value
const book = Book.fromJSON('{"title":"Notes"}');
book.pages; // 0
book.tags.length; // 0
book.author.first_name; // ""
```

## Types From Another Proto File

A message defined in an imported proto is generated into that file's own output, so a reference
to it becomes an import:

```proto
// common/types.proto
syntax = "proto3";
package common;
option go_package = "example.com/gen/common;commonpb";

message Address { string city = 1; }
```

```proto
// a/msg.proto
syntax = "proto3";
package app;
option go_package = "example.com/gen/a";
import "common/types.proto";

message Msg { common.Address addr = 1; }
```

| Language   | Import                                     | Reference           |
| ---------- | ------------------------------------------ | ------------------- |
| Go         | `commonpb "example.com/gen/common"`        | `commonpb.Address`  |
| C++        | `#include "common/types.h"`                | `::common::Address` |
| Python     | `import common.types as types`             | `types.Address`     |
| TypeScript | `import * as types from '../common/types'` | `types.Address`     |

The import points at _this plugin's_ output for the imported proto, so that file has to be
generated too. Pass the whole dependency closure to one `protoc` invocation:

```bash
protoc --struct_out=. --struct_opt=go a/msg.proto common/types.proto
```

Referring to a type from a file that is not being generated is an error naming the file. That is
also what a field of a well-known type such as `google.protobuf.Timestamp` hits — those live in
protos this plugin does not generate, so use an `int64` unix timestamp or a string instead.

Go is the one language whose import needs a module path, and `go_package` is the only place a
descriptor carries one. Generating Go for a file that references a proto without a `go_package`
option is reported as an error rather than emitting a name nothing defines.

Python imports a generated module by its path, so a proto path containing a segment that is not a
Python identifier (`my-pkg/types.proto`) cannot be imported by another generated module. That is
reported when it would matter; the other three languages are unaffected.

## Optional Fields

Given this input:

```proto
syntax = "proto3";
package myapp;

message Person {
  string first_name = 1;
  optional string middle_name = 2;
  optional int32 height_cm = 3;
}
```

### Go

`optional` generates a pointer, tagged `omitempty`. A nil pointer is left out of the encoded
output; a pointer to the zero value is still written, which is what distinguishes "unset" from
"set to the zero value":

```go
type Person struct {
	FirstName string `json:"first_name" yaml:"first_name"`
	MiddleName *string `json:"middle_name,omitempty" yaml:"middle_name,omitempty"`
	HeightCm *int32 `json:"height_cm,omitempty" yaml:"height_cm,omitempty"`
}
```

```go
person := &Person{FirstName: "Ada"}
data, _ := person.ToJSON()
// {"first_name":"Ada"}

middle := "Byron"
person.MiddleName = &middle
data, _ = person.ToJSON()
// {"first_name":"Ada","middle_name":"Byron"}

empty := ""
person.MiddleName = &empty
data, _ = person.ToJSON()
// {"first_name":"Ada","middle_name":""} -- set, and distinguishable from unset
```

### C++

`optional` wraps the member in `std::optional`, and the serializers skip a field that has no
value. `FromJSON` and `FromYAML` treat an explicit null as "not set":

```cpp
struct Person {
  std::string first_name;
  std::optional<std::string> middle_name;
  std::optional<int32_t> height_cm;

  nlohmann::json ToJSON() const {
    nlohmann::json j;
    j["first_name"] = this->first_name;
    if (this->middle_name.has_value()) {
      j["middle_name"] = *this->middle_name;
    }
    if (this->height_cm.has_value()) {
      j["height_cm"] = *this->height_cm;
    }
    return j;
  }

  void FromJSON(const nlohmann::json& j) {
    this->first_name = std::string{};
    if (j.contains("first_name") && !j["first_name"].is_null()) {
      this->first_name = j["first_name"].get<std::string>();
    }
    this->middle_name = std::optional<std::string>{};
    if (j.contains("middle_name") && !j["middle_name"].is_null()) {
      this->middle_name = j["middle_name"].get<std::string>();
    }
    // ... (height_cm follows the same pattern)
  }
};
```

Every member is reset before the key is read, so decoding into a struct that already holds values
replaces them rather than merging: `FromJSON` is a full load, not a patch. That matches the other
three, whose decoders build a new message from scratch.

```cpp
myapp::Person person;
person.first_name = "Ada";
if (!person.middle_name.has_value()) {
  // the field was never set
}
person.middle_name = "Byron";
```

### Python

`optional` annotates the field as a union with `None`, defaulting to `None`. `to_dict` leaves an
unset field out entirely, matching the other three generators:

```python
@dataclass
class Person:
    first_name: str = ""
    middle_name: str | None = None
    height_cm: int | None = None
```

```python
person = Person(first_name="Ada")
if person.middle_name is None:
    ...  # the field was never set

person.to_json()  # {"first_name": "Ada"}
```

### TypeScript

`optional` makes the property optional, so it may be left off the object entirely:

```typescript
export interface Person {
  first_name: string;
  middle_name?: string;
  height_cm?: number;
}
```

```typescript
const person: Person = { first_name: "Ada" };
if (person.middle_name === undefined) {
  // the field was never set
}
```

person := &Person{FirstName: "John", LastName: "Doe", Age: 30}

# Create
person = Person(first_name="John", last_name="Doe", age=30)

## Reserved Words

A proto field whose name is a reserved word in the target language is renamed by appending an
underscore. Only the member is renamed — the serialized key is always the proto field name, so
the wire format is unaffected and the four languages stay interoperable.

```proto
message Msg {
  string from = 1;
  string class = 2;
  int32 operator = 3;
}
```

```python
@dataclass
class Msg:
    from_: str = ""
    class_: str = ""
    operator: int = 0    # not a Python keyword, so left alone
```

```cpp
struct Msg {
  std::string from;         // not a C++ keyword, so left alone
  std::string class_;
  int32_t operator_ = 0;
};
```

```json
{ "from": "f", "class": "c", "operator": 7 }
```

## Interoperability

All four generators serialize under the proto field name, so output written by one is readable by
the others:

```
Go      {"first_name":"Ada","address":{"city":"London"},"middle_name":"Augusta"}
Python  {"first_name": "Ada", "address": {"city": "London"}, "middle_name": "Augusta"}
```

An unset `optional` is omitted by all four, and each rebuilds it as its own "absent" value: `nil`
in Go, an empty `std::optional` in C++, `None` in Python, and a missing property in TypeScript.

Reading is lenient everywhere, which is what lets the four interoperate despite not making
identical choices about what to emit:

| Input                                        | Result                                   |
| -------------------------------------------- | ---------------------------------------- |
| a field the writer left out                  | its zero value (`nil` for an `optional`) |
| an explicit `null`                           | treated as absent                        |
| an empty list or map vs. a missing one       | interchangeable                          |
| an empty document (`{}`, `null`, empty YAML) | a fully zero-valued message              |

Go omits an empty `repeated` field or map, since a nil slice would otherwise encode as `null`;
C++ and Python write `[]`/`{}`. Both forms load correctly in all four languages.

Integer map keys are written as strings in JSON, as JSON requires, and converted back on read, so
`map<int64, T>` round-trips as the declared type:

```python
u = U(profiles={7: P(bio="b")})
u.to_json()                    # {"profiles": {"7": {"bio": "b"}}}
U.from_json(u.to_json()) == u  # True -- the key is an int again
```

Go, C++ and Python all get the declared key type back. TypeScript cannot: a JavaScript object key
is a string however it is assigned, so the generated `Record<number, T>` lets you index by a
number — `u.profiles[7]` finds the entry — while `Object.keys(u.profiles)` still yields `["7"]`.
The decoder does parse each key, so a document written with a non-canonical key (`"007"`) still
lands where indexing by `7` finds it.
